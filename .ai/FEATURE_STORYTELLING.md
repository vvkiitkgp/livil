Using all existing documentation inside the `.ai` folder and the repository, create a comprehensive `FEATURE_STORYTELLING.md`.

This document should define how LiViL transforms product features into compelling stories.

The goal is NOT to create marketing.

The goal is to help people understand why a feature exists.

Every feature should have a narrative.

The document should explain how to identify that narrative before any content is created.

---

# Philosophy

Features are not stories.

Problems are stories.

Decisions are stories.

Tradeoffs are stories.

Iterations are stories.

Failures are stories.

Users connect with stories—not feature lists.

---

# Story Discovery Framework

Before creating any content, answer:

What problem existed?

Who experienced the problem?

Why was solving it important?

What alternatives were considered?

Why were they rejected?

What engineering challenges appeared?

What design challenges appeared?

What compromises were made?

What surprised us?

What changed because of this feature?

How does the user benefit?

What did we learn?

---

# Questions Before Publishing

Does this story teach something?

Does it explain why?

Would someone care even if they never use LiViL?

Does it celebrate craftsmanship?

Is there a stronger angle?

Could this become multiple posts instead of one?

---

# Long-Term Principle

LiViL should become known for telling stories about building products—not for announcing features.

Every feature deserves a story.

Not every story needs a feature.
